## 2026-11-24: step 3, prompts written by a cloud model and ranked by coverage

- Asked for: "Next work", step 3 of the plan.
- The spec's split (§6): an LLM proposes, a deterministic analyser decides. The writer is strata-models' new `write` role (Claude Sonnet 5.5 by default, strata-models#119), so the model choice lives with the other roles; the app sends a brief (the sounds said least, each with a word that has it, the sentence types and styles said least) and a JSON schema, and checks every candidate (3 to 30 words, no digits because the recogniser may write "23" or "twenty-three", a known kind and style). A candidate's key is a hash of its words and cue, so a prompt written twice is one prompt. Only the prompts' words leave the computer.
- Phonemes come from espeak-ng's `en-gb-x-rp` voice, not plain `en-gb`: plain `en-gb` gives "bath" the vowel of "trap", which does not match an RP inventory. The inventory is RP's 44 less /ʊə/: espeak's RP (like today's RP) merges it into /ɔː/ ("poor" = "pour"), so it would never be said and the ranker would chase it for ever. Run on the starter set's 25 read prompts, every one of the 43 is said at least once (the least, /ɜː/ and /ɔɪ/, twice), which is why the ranker weighs how often a unit is said, not only whether.
- The ranker is the spec's utility (§7.1) with the terms that can be measured before a model exists: each unit a prompt has is worth its group's weight over one plus the times it has been said; that is divided by the seconds the prompt costs (4 s to set up, 2.5 words a second, 2 s more with a cue), and cut by its content-word overlap with what is already recorded or ranked above it. Greedy, so a queue of ten does not all chase the same rare sound. 120 candidates rank in about 0.4 s. Weights and timings are first guesses for the pilot.
- Ranking runs every 5 usable takes (§7.3: every 5 to 10), after a batch is written, and by `strata-voice rank`. The starter set keeps its order first, generated prompts after it.
- Styles: the W3C EmotionML everyday categories that suit mild everyday speech, plus neutral and four stances (sarcastic, sympathetic, reassuring, whispered). The spec leaves stance against emotion open (§15); the vocabulary is versioned in the manifest (`strata-voice-everyday-1`).
- The manifest now carries each prompt's phonemes, its style (`requested_style.category`) and the writer.
- Not done: teacher disagreement and student error in the score (need a model), held-out generated prompts, an accent other than RP (a different espeak voice needs its own inventory), and setting `espeak` from the Settings screen (`strata-voice set espeak ...` does it).

## 2026-11-24: auto-crop and score

- Asked for: step 2, prompted takes only (Jonathan has not much existing audio yet and will gather it later).
- A take is judged before the upload answers, so the studio can ask again at once. Levels are judged here in under a second; the words wait on strata-models for up to 30 s at `high` priority (someone is at the microphone). When the service is not running, busy past that, or the job fails, the take is `unchecked`: kept and counted, never refused for the service's sake, and `strata-voice score` judges it later, which can send its prompt back to the queue.
- Whisper is not given the prompt as `initial_prompt`: it would pull the transcript towards the prompt and hide the misreadings the check is for.
- The crop is two numbers on the take (`speech_start`, `speech_end`: 0.15 s before the first word, 0.25 s after the last), played through `MediaPlayer`'s `window` with the whole timeline shown, and written to the manifest. The master stays the one lossless file; a training tool cuts it.
- The noise floor is the quietest tenth of 20 ms windows, so a take needs some quiet in it. Real takes have it (the moment between pressing Record and speaking); the tests' tones did not, which is why `tests/utils/takes.py` makes speech-like WAVs.
- No "starts too soon" or "ends too soon" check yet: Whisper's word times at the very edges of a clip are not reliable enough to refuse a take on. The pilot (step 4) decides whether it is needed, and tunes the thresholds in `scoring.py` (clipped above 2 samples, quiet below a -30 dBFS peak, noisy above a -48 dBFS floor, at most 10 % of the words wrong).
- A misread take can be kept anyway (`accepted`): names and rare words the recogniser does not know would otherwise block a prompt for good.
- The level and word-error code is shared: `wav.measure` and `wer` went into strata-python (#65), since strata-models' transcription evals compute the same word error rate. Until released, `pyproject.toml` takes strata-python from that PR's commit.

## 2026-11-23: the studio shell, on shared recording code

- Asked for: a recording studio first (prompts, then auto-crop and scoring that asks for new takes), spoken voice before written, local first with cloud models allowed for writing prompts, and strata-models hosting the models while this app orchestrates. Then: put the common code in strata-react and strata-python.
- Capture is an AudioWorklet, not MediaRecorder: MediaRecorder writes only Opus or AAC, and training needs the samples as they were. Echo cancellation, noise suppression and automatic gain are off for the same reason. The worklet posts 2048 frames at a time (about 23 messages a second at 48 kHz) rather than every 128-frame quantum.
- Takes upload as a raw `audio/wav` body, not multipart: one file per request, no form parsing, and the size is checked from `Content-Length` (64 MB) before the body is read. The server checks the header with `strata_python.wav.read_wav` (mono, 16 or 24-bit, 16 kHz and up, 0.3 seconds to `max_take_seconds`).
- A take's row is flushed first for its id, the file is written atomically as `human/take_<id>.wav`, and only then is the row committed, so a failed write leaves neither. Ids never go back (`sqlite_autoincrement`), so a file name is never reused.
- Consent is a setting (`consented_on`), checked by the server before any take is kept, so a client cannot record around it.
- Skipping is an undoable removal on the client (`useUndoable`) over a server queue of the next ten prompts, so the next prompt shows at once while Undo is in reach.
- A take keeps the folder it was written to (`takes.root`): the Settings hint promises earlier takes stay where they are, and with only a relative path they were looked for in the new folder. Removing a take deletes its file before its row, so a failure leaves something to retry.
- The app has no login. It listens on 127.0.0.1, which is the intended use (one speaker, one computer); a deployment reachable from elsewhere needs an authenticating proxy (docs/deploying.md).
- Moved to the libraries (Jonathan: "a lot of the audio components should be common UI stuff"): the microphone, recorder, WAV writer, level meter and verdict to strata-react (#303), the WAV check and test WAVs to strata-python (#50). Moving them found a bug: the old check wrote `{e or 'it ends early'}`, and an exception is always truthy, so a truncated file's sentence ended in "()". Both now come from their registries: strata-react `^1.3.4` from npm and strata-python `>=0.2.9` from PyPI (the first releases with `useRecorder` and `wav`). 0.2.9 also released main's `ApiModel` contracts, so `Page.total` and `Folder.free_bytes`/`total_bytes` are required in the schema: the web mocks send them and the takes screen's `next ?? null` is gone.
